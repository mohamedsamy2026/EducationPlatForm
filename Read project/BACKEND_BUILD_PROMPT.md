أنت مهندس Backend بتنفّذ ربط مشروع «الغازي في التاريخ» بـ Supabase وCloudinary (وروابط Google Drive/YouTube). المشروع React + Vite + Tailwind، والواجهة كلها شغالة حاليًا على بيانات تجريبية (mock) محلية. مهمتك تحويلها لـ Backend حقيقي من غير ما نغيّر الواجهة.

## المرفقات
1. فولدر المشروع (الكود الحالي).
2. `BACKEND_PLAN.md`: **التصميم المعتمد**: الجداول (21)، العلاقات، RLS، الدوال، الصور، ترتيب التنفيذ. نفّذه كما هو. أي اختلاف أو تحسين تقترحه، اكتبه لي واستنى موافقتي قبل ما تنفذه.
3. (اختياري) `STUDY_MAP.md`: خريطة ملفات المشروع.

## الصلاحيات والأمان (التزم بيها حرفيًا)
- اشتغل على مشروع Supabase **تجريبي (dev)** فقط. لا تلمس أي مشروع إنتاج.
- أي أمر مدمّر (حذف جداول/بيانات، reset، تغيير policies على بيانات موجودة) **اطلب موافقتي عليه قبل التنفيذ**.
- كل تغييرات قاعدة البيانات تتكتب كـ **migrations** في `supabase/migrations/` بأرقام مرتبة. ولا تغيّر في قاعدة البيانات من غير migration.
- ممنوع أي مفتاح سري (service role، Cloudinary API secret، Google tokens) في كود الـ frontend أو في Git أو في ردودك. الأسرار في **Supabase Edge Function secrets** وملفات `.env` المتجاهلة. وفي الـ frontend بس: `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` و`VITE_CLOUDINARY_CLOUD_NAME`.
- لو محتاج مني مفتاح أو إعداد، قولي إيه هو وإزاي أحطه، وما تطلبش مني أكتبه في الشات.

## قواعد المعمارية (غير قابلة للتفاوض)
1. **الصفحات والمكونات ما تكلمش Supabase مباشرة.** كل شيء يمر على `src/services/`. ولا تغيّر في تصميم الواجهة (ألوان، خط، Tailwind، شكل الصفحات).
2. **حافظ على أسماء دوال الـ services ومدخلاتها وشكل مخرجاتها** (camelCase بنفس الحقول الحالية). اعمل طبقة `src/mappers/` تحوّل snake_case لـ camelCase، بحيث الصفحات ما تتغيرش.
3. ملفات `src/data/` تفضل كمرجع للبيانات التجريبية ومنها تطلع ملفات الـ seed. مفيش صفحة تستوردها.
4. الدوال `async`، ومقارنة الـ IDs بـ `String(a) === String(b)` حيث يلزم، والنصوص العربية للحالات من `src/constants/statusLabels.js`.
5. أي عملية متعددة الخطوات (قبول طلب، تصحيح، حذف متسلسل) = **دالة RPC واحدة** أو CASCADE، مش خطوات من المتصفح.
6. **المبالغ تتحسب في السيرفر** (من `course_plans` و`books.price`)، ومش من المتصفح.
7. **الإجابات الصحيحة ما توصلش لمتصفح الطالب أبدًا.** تصحيح الأسئلة التلقائية في `submit_exam`، والامتحان مرة واحدة لكل طالب (قيد unique).
8. روابط الفيديو والملزمة تتجاب بـ `get_lesson_media` بعد فحص اشتراك الطالب أو صلاحيته للدرس.
9. RLS مفعّل على **كل** جدول، والطالب ما يقدرش يغيّر `profiles.role`.
10. مكتبات جديدة مسموحة: `@supabase/supabase-js` و`browser-image-compression` فقط. أي غيرها اسألني الأول.
11. لا تعدّل أي ملف خارج نطاق المرحلة. ولا تصلّح أخطاء الـ lint القديمة (في Chat وLessonPage وExamTimer وCourseDetails وDashboardResults) إلا لو لمستها بالفعل.

## قرارات محسومة
- **الشات:** جدول رسائل بسيط بين الطالب والمستر (`sender_role` = student/teacher).
- **الدخول:** بالإيميل والباسورد. ولو كتب رقم تليفون، دالة `resolve-login` تجيب الإيميل. وتأكيد الإيميل مش مطلوب حاليًا.
- **حساب المستر:** يتعمل مرة واحدة يدويًا، و`role='admin'` بـ SQL (اشرحلي الخطوات).
- **اشتراك الحصة المدفوع ملغي:** شيل فرع `accessType = "lesson"` من `subscriptionService`، والدرس الفردي بصلاحية من المستر.
- **بيانات البداية (seed):** الصفوف الستة، ووسيلة الدفع، والإعدادات، **بالإضافة إلى ملف منفصل** `seed_demo.sql` للمحتوى التجريبي (كورسات، وحدات، دروس، امتحانات، أسئلة، كتب) **بدون طلاب وهميين**. الطلاب التجريبيين أعملهم أنا من الموقع.
- **الصور:** ضغط في المتصفح بـ `browser-image-compression` (أقصى بُعد 1600px، WebP، حوالي 300KB، Web Worker)، ثم رفع موقّع لـ Cloudinary عبر Edge Function `cloudinary-sign` (للمستر فقط)، وحفظ `image_url` + `image_public_id`، وحذف الصورة القديمة عند الاستبدال أو الحذف عبر `cloudinary-delete`.
- **عداد المساحة:** `storage-usage` (للمستر فقط) يرجّع Supabase وCloudinary. وGoogle Drive يتأجل لآخر مرحلة وبموافقتي (محتاج OAuth).

## مراحل التنفيذ (اقف بعد كل مرحلة وانتظر موافقتي)
1. **الأساس:** migrations للجداول والعلاقات وRLS والـ helper functions وseed الأساسي.
2. **القراءة العامة:** services الصفوف والكورسات والخطط والوحدات والدروس والكتب ووسائل الدفع.
3. **الحسابات:** `authService` وتسجيل الحساب (trigger ينشئ الـ profile) والدخول (+ بالتليفون) و`AuthContext` و`getCurrentStudent` وحماية المسارات (`ProtectedRoute` و`AdminRoute`).
4. **رحلة الطالب:** الاشتراكات، الدروس (`get_lesson_media`)، الامتحانات (`get_exam_questions` و`submit_exam`، وشيل `sessionStorage`)، النتائج، طلبات الاشتراك والكتب، ملكية الكتب.
5. **لوحة المستر:** خدمة خدمة (الطلاب، الكورسات، الامتحانات، النتائج، الاشتراكات، طلبات الكتب، الكتب، الصلاحيات، الإعدادات) مع دوال القبول والرفض والتصحيح والتمديد والإنهاء والحذف المتسلسل و`delete-student`. فلترة وتقسيم وإحصائيات على مستوى الـ query، مش بتحميل الجداول كلها.
6. **الصور:** `mediaService` والضغط والرفع والحذف.
7. **المساحة والتصليب:** `storage-usage`، ومراجعة الأسرار، واختبار شامل.

## الاختبارات المطلوبة (اكتبها ونفّذها وورّيني النتيجة)
اختبر RLS والدوال بأربع هويات: زائر، طالب A، طالب B، مستر. وأقل الفحوصات:
- الزائر يقرا الكورسات المنشورة والكتب فقط، ولا يقرا `lesson_media` ولا الامتحانات.
- الطالب مش مشترك: `get_lesson_media` و`get_exam_questions` يرفضوا.
- الطالب مش بيقرا `question_answers` أبدًا، ولا نتائج طالب تاني.
- تسليم نفس الامتحان مرتين يفشل.
- الطالب مش بيقدر يغيّر `role` ولا يضيف نفسه اشتراكًا.
- إرسال `amount` مزوّر في طلب اشتراك أو كتاب بيتجاهل، والسيرفر يحسبه.
- `transaction_id` مكرر (حتى بين جدول الاشتراك والكتب) يترفض.
- قبول طلب مرتين يفشل. وقبول طلب كتاب بيسجّل الملكية، وحذف الطلب بعدها ما بيمسحهاش.
- `grade_essays` تحسب الدرجة النهائية = تلقائي + مقالي، وتحفظ درجة كل سؤال لوحدها.
- حذف كورس/كتاب/طالب بيمسح كل المرتبط به ولا يمس غيره.
